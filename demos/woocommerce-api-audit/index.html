Sample diagnostic checklist

WooCommerce Order Flow & API Audit

This sample shows the kind of diagnostic structure used before touching a live WooCommerce store. It is designed for problems where paid orders fail to reach a CRM, supplier, fulfillment system, warehouse, or external API.

What we check first

1. Order state

Which WooCommerce status triggers the integration: pending, processing, completed, paid, refunded, failed?

2. Payment boundary

Whether payment confirmation happens before the outbound API call or after an async webhook.

3. API authentication

Keys, signatures, token expiry, IP allowlists, environment mismatch, and test vs production endpoints.

4. Payload shape

Required fields, SKU mapping, customer data, shipping logic, currency, tax, and validation errors.

5. Retry behavior

What happens when the external API is down: duplicate orders, silent failure, manual retry, or logging.

6. Safe repair path

What can be checked from logs first, what needs staging, and what should not be changed directly in production.

Typical output

  • Likely failure point and confidence level.
  • Missing access or logs needed for confirmation.
  • Smallest safe fix to try first.
  • Production risks that require backup or staging before changes.

What this is not

This is not a blind promise to repair every integration immediately. It is the first step that prevents expensive guessing.
