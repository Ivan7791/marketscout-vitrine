What to send before a diagnostic review

This keeps the first step safe. We can usually start with public information, screenshots, logs, and a clear description before asking for any access.

Send this first

  • Website URL.
  • What is broken or suspicious.
  • When it started and what changed before it appeared.
  • Screenshots or exact error messages.
  • Relevant plugin/theme names and versions if known.
  • For WooCommerce/API: one example order ID, expected result, actual result, and any API/log error.

Do not send yet

  • No passwords in the first message.
  • No payment details, customer private data, or full database exports.
  • No production admin access until the diagnostic path requires it and the access boundary is agreed.
